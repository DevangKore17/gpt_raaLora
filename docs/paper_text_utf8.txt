RaaLoRA: Rank Adaptive low-rank Adaptation
Devang H. Kore, Shubham Khandekar, Adnan Khan
Abstract- 
INTRODUCTION
Deploying Large Language Models (LLMs) in real applications is difficult because they need a lot of memory and compute power. To adapt these models for specific tasks on normal hardware, Parameter-Efficient Fine-Tuning (PEFT) methods are commonly used. LoRA is the most popular PEFT method [1]. LoRA keeps the original model weights frozen and adds small trainable low-rank matrices to the transformer layers. This reduces the number of parameters we need to update during backpropagation, which saves resources.
But standard LoRA uses the same rank value (e.g.,  
HYPERLINK "https://www.codecogs.com/eqnedit.php?latex=%20r%20%3D%208%20" \l "0"
 ) across all layers. This is not optimal because different layers have different requirements. Some layers process complex semantic information and need a higher rank. Other layers only deal with basic syntax and need very few changes. Using the same rank everywhere wastes VRAM on layers that do not actually need deep modifications [1].
Researchers have proposed two main approaches to fix this problem: static allocation and dynamic routing. Static methods like AdaLoRA [2] use SVD metrics to assign different ranks to different layers. This works mathematically, but continuously tracking and updating these high-dimensional SVD matrices during training adds a lot of extra parameter overhead. Dynamic routing methods like FlexiLoRA [3] use a gating network to decide token-level importance on the fly. This is effective, but the router stays active during deployment. This adds extra computations for every token during inference, which creates latency [3].
We propose RAALoRA. Our method uses dynamic routing only during training. After training, we use average pooling to convert the token-level scores into a fixed layer-level metric. We then prune the network to match this rank map and delete the router permanently.
Our contributions are:
 - We introduce a routing mechanism that works during training but does not affect deployment.
- We use average pooling to create static layer ranks from dynamic token scores for pruning.
- We show that RAALORA removes inference latency, uses only 0.86% trainable parameters, and achieves a competitive loss of 2.0626.
 Literature Review
2.1 Background on Parameter-Efficient Fine-Tuning
A few years ago, fine-tuning meant updating all the weights of a neural network. For models with billions of parameters, this was a big bottleneck. Researchers started using adapter modules, which are basically small extra networks added between the main layers. This saved memory during training. But people soon realized that these extra layers made the model slower when it was making predictions because the data had to travel a longer path. This led to the idea of Low-Rank Adaptation, which mathematically merges the extra weights back into the main model so that no extra time is taken.
2.2 Dynamic Routing in Neural Networks
Instead of passing data through the whole network, conditional computation or dynamic routing tries to pass data only through specific parts of the network. The most famous example is Mixture of Experts (MoE). While this is great for increasing the model's knowledge without increasing the computational cost too much, the router itself takes up memory and processing time. Also, training a router is tricky because choosing between "Layer A" and "Layer B" is a hard yes-or-no decision, which stops the normal gradient flow in neural networks. Researchers solved this using smoothing techniques like Gumbel-Softmax, but the inference delay problem was still left unsolved.
2.3 Structural Pruning
Pruning means cutting out the useless weights of a model to make it lighter and faster. If we just randomly delete weights (unstructured pruning), the model doesn't actually run faster on modern GPUs because the memory becomes fragmented. To get real speed improvements, we have to delete entire rows or columns (structural pruning). The literature shows that pruning a model while it is training usually ruins the accuracy. The best way, as suggested by many authors, is to train a slightly bigger model first, find out which parts are actually useful, and then cut out the rest before deploying it to the real world.

Out of the total samples in the data subset we used 1500 samples for initial learning and 800 samples for the routing and final polishing stages. unsloth/Llama-3.2-1B-Instruct was the base architecture we used, and loaded in 4-bit quantization with a maximum sequence length of 4096 tokens.

So we can say that RaaLoRA has successfully managed to preserve the semantic meaning of the generated text despite the highly reduced parameter count.
4 conclusion:
1.We removed the bottleneck between budget allocation(which adds parameter overhead) and dynamic routing(which adds latency during inference) by pruning dynamic routing of tokens to their ranked  layers during inference so our model learned optimal and layer specific ranks dynamically during training while being entirely specific during deployment(inference)
2.Although our model has a competitive loss of 2.0626 we only updated 0.86% of the trainable parameters retaining the generalised intelligence of the base model
3. Our research emphasizes on allowing our highly specialized and dynamically optimized large language model to be integrated in  retail-grade hardware allowing making small enterprises to integrate AI  in drastically more efficient way
